# StackAlign

A standalone Bash-based LEMP installer and manager for supported EL-family Linux systems on x86_64.

## Project status — 12 November 2026

**The M2a tuning engine is implemented on `main`; its contract documentation remains under review in PR #1. StackAlign is not yet a complete installer and is not production-validated.**

- `lib/tune.sh` implements the lean and standard M2a profiles, including reserve decomposition, strict numeric validation, worker-aware connection sizing, workload/role validation, advisory warnings, and explicit refusal behavior.
- `tests/test_tune_math.py` contains the T1–T28 arithmetic contract tests. The pinned floors are T27 = 391 MiB and T28 = 3389 MiB.
- PR #3, which delivered the M2a implementation and contract tests, was merged into `main`. Its Ubuntu 24.04 and AlmaLinux 9 CI jobs passed: [workflow run](https://github.com/ljrseals-dev/StackAlign/actions/runs/43251330070).
- The M2a tuning contract and related documentation are being reviewed in open PR #1, branch `work/initial-bootstrap`.
- CI repair work remains in open PR #2, branch `fix/ci-lint-and-executable-mode`. Its recorded workflow passed Ubuntu and AlmaLinux 9 jobs for the revision tested; the branch has since diverged from `main` and must be reconciled before merge.

## What is not yet done

- `SA_PHP_CHILD_MIB` and fixed service costs remain **assumptions, not measurements**. M2b must replace them with measurements from representative real hosts.
- The 512 MiB no-swap floor is verified arithmetically (T3: one PHP child, 48 MiB buffer). It has not been load-tested on a real 512 MiB VM.
- Isolation, backup, routines, WordPress hardening, and the remaining LEMP modules are designed or planned but are not implemented as a complete, validated system.
- No measured sizing table is published. Sizing output must be generated by running `lib/tune.sh`, not typed by hand.
- EL 10 validation and real-host installation/runtime validation have not been established.
- Production readiness is not claimed.

## Scope

StackAlign manages LEMP servers and supported self-hosted PHP application workloads. X-Cart 5.6 is a warning-only workload profile, not an installation target. Hosted SaaS and non-LEMP application domains are excluded.

## Operating principles

- Bash for the installer and runtime. Python only for development-time tests and benchmarks.
- EL-family x86_64 is the intended deployment scope. Ubuntu 24.04 is a CI target only, not a supported deployment target.
- No unattended update application.
- No secrets in the repository, logs, snapshots, or Git history.
- No telemetry, network bootstrap, or hidden remote configuration.
- No unmeasured performance, memory, security, or recovery-time claims.
- Sizing formulas and normative arithmetic belong in `docs/TUNING.md`; generated sizing output must come from the implementation.

## Development

Use focused feature branches and pull requests. Preserve existing history and never force-push. Keep `main` protected from unreviewed changes. A merge is not evidence of a successful build, installation, or production operation; report CI and target-host validation separately.
